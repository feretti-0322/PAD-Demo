A. WebDriver でブラウザを起動する

「新しい Chrome を起動する」アクションを配置し、「操作方法」プルダウンで「Webdriver」を選択。URL には以下のデモサイトのトップを指定します：

https://feretti0322.github.io/PAD-Demo/
💡 「Cookie をクリア」をオンにすると挙動が安定します： アクション設定下部の「Cookie をクリア」トグルをオンにしておくと、前回ログイン情報などが残ったまま起動して動作がブレるのを防げます。研修中はオンにしておくと、毎回まっさらな状態から再現できて快適です。
操作方法プルダウンに「Webdriver」が出ない／起動でエラーになる場合は、第1回 の ChromeDriver 配置パスを再確認してください。
🛠️ ハンズオン課題①：WebDriver 起動でデモサイト https://feretti0322.github.io/PAD-Demo/ にアクセスするフローを作り、実行ボタン（▷）を押してブラウザが立ち上がった状態にしておきましょう。
※ この後の 4-B で UI 要素ピッカーを使うので、立ち上げた Chrome は閉じずにそのまま残しておくのがポイントです。

B. メールアドレスを入力する 〜UI 要素ピッカーの使い方〜

📌 ここがキモです： ブラウザ自動化の成否は 「PAD に Web ページ上の正しい部品（UI 要素）を覚えさせられるか」 にかかっています。アクションの配置自体は数クリックで終わりますが、UI 要素ピッカーを正しく扱えないと、何を入力しても狙った欄に入りません。ここで丁寧に手順を体に入れます。
⚠️ 事前準備：Microsoft Power Automate 拡張機能を Chrome に入れる（必須）
UI 要素ピッカーは Chrome の拡張機能が ON になっていないと反応しません。4-B に入る前に、必ず下記の手順で拡張機能を有効にしてください。
  1. 4-A のハンズオン課題①で立ち上げた Chrome（デモサイトが開いているもの）の「+」ボタンで新しいタブを開く
  2. 下の Chrome ウェブストアの URL にアクセス：
    https://chromewebstore.google.com/detail/microsoft-power-automate/ljglajjnnkapghbckkcmodicjhacbfhk
  3. 「Chrome に追加」をクリック → 確認ダイアログで「拡張機能を追加」
  4. 追加後、Chrome 右上のパズルピース 🧩 アイコンから 「Microsoft Power Automate」 がオン（青色）になっていることを確認

この拡張機能が入っていれば、次のステップで PAD からブラウザに切り替えたときに赤枠ハイライトが出るようになります。

① アクションを配置する
左のアクション一覧から「ブラウザー自動化 ＞ Web フォーム入力 ＞ Web ページ内のテキストフィールドに入力する」をフロー上にドラッグ＆ドロップします。設定ダイアログが開いたら、「UI 要素」 欄の右にある ▼ →「UI 要素の追加」 をクリック。

② UI 要素ピッカーが起動する
画面に 「UI 要素ピッカー」 のオーバーレイが出ます。この状態のままブラウザのどこかを 1 回クリックすると、以降マウスを乗せた要素が赤枠でハイライトされるようになります。

③ ブラウザ上で対象の部品にマウスを合わせる
Chrome 側の メールアドレス入力欄 にマウスカーソルを合わせると、その要素が 赤い枠線 で囲まれます（左の画像の状態）。
この赤枠が「いま PAD に覚えさせようとしている部品」です。狙いたい欄に正しく枠が乗っているか必ず目で確認してください。

⚠️ よくあるミス： ボタンの外側のラベルや、入力欄を包んでいるカードの外枠に赤枠が乗ってしまうことがあります。その状態で確定すると、後で入力アクションが失敗します。枠の大きさが入力欄ぴったりに重なる位置でホバーしてください。

④ Ctrl ＋ クリックで要素を確定する
赤枠が正しい位置に乗ったら、Ctrl キーを押しながら左クリックします。これで PAD に「この部品を覚える」と指示が入ります。
※ ただクリックすると Web ページのリンクが反応してしまうので、必ず Ctrl を押しながらクリック。

⑤ アクション設定に戻り、入力テキストを指定する
「Web ページ内のテキストフィールドに入力する」アクション設定で：
  • UI 要素：先ほど取得したメール入力欄を選択
  • テキスト：自分のメールアドレス（例：shimura.fellows@gmail.com）
「保存」で確定します。
⑥ PAD の「UI 要素」ペインに登録される
PAD の編集画面に戻ると、右側の 「UI 要素」ペイン に取得した要素が追加されています（例：Input text 'email'）。
この要素はフロー内のどのアクションからでも再利用できます。
💡 名前の変更も可能： 右クリック →「名前の変更」で自由にリネームできます。
⑦ セレクタを確認しておく（任意 / トラブル時のために）
UI 要素を右クリック →「編集」を選ぶと、PAD が内部で覚えているセレクタ（例：#email や input[type='email']）を確認できます。
ふだんは触らなくて OK。ただし「要素が見つかりません」エラーが出たときは、ここを開いてセレクタが想定どおりか確認するクセをつけておくと、原因が一発で分かります。
🛠️ ハンズオン課題②：UI 要素ピッカーを使ってメール入力欄を取得し、自分のメールアドレスを入力するアクションを完成させてください。

C. パスワードを『直接暗号化されたテキスト』として保持する（必修）

通常のテキスト入力欄にパスワードをそのまま書くと、フローを誰かに共有したときに PW も漏洩します。PAD にはテキスト欄横のプルダウンで「直接暗号化されたテキストの入力」という選択肢があり、これを選ぶと値が暗号化されてフロー編集画面でも復元できなくなります。

  1. 「Web ページ内のテキストフィールドに入力する」アクションをもう1つ配置
  2. UI 要素ピッカーで パスワード入力欄 を取得（4-B と同じ手順）
  3. テキスト入力欄の右側にあるプルダウン（▼）をクリック
  4. 「直接暗号化されたテキストの入力」を選択
  5. パスワードを入力して保存 → 暗号化された状態で保持される
⚠️ 注意： 暗号化テキストは PAD 内でしか復号できません。フローを共有しても他人がパスワードを盗み見ることはできません。最終演習ではこの方式が必須です。
🛠️ ハンズオン課題③：パスワードを「直接暗号化されたテキストの入力」で保持し、PW 入力欄に入力するアクションを追加してみましょう。

D. チェックボックスON＋ボタンクリック

📌 アクションが見つけづらい場所にあるので注意： これから使う「Web ページのチェックボックスの状態を設定します」と「Web ページのボタンを押します」は、アクションペインの 「ブラウザー自動化 ＞ Web フォーム入力」 カテゴリの下のほうに置かれています。テキスト入力のアクションと同じ場所をスクロールして探してください（左の画像の矢印の位置）。
  1. Web ページのチェックボックスの状態を設定します：UI 要素ピッカーで 利用規約チェックボックス を取得 → 状態＝オン
  2. Web ページのボタンを押します：UI 要素ピッカーで ログインボタン を取得 → クリック
どちらのアクションも UI 要素の取得手順は 4-B とまったく同じです。ホバー → 赤枠確認 → Ctrl ＋ クリック、の流れを繰り返します。
🛠️ ハンズオン課題④（最終課題）：規約チェックを ON →ログインボタン押下 → ログイン成功で pad-overview.html に遷移することを確認してください。

E. ログイン失敗時の動作

故意に PW を間違えてログインすると、画面上にエラーメッセージが表示されます。PAD の初期設定では、何かしらエラーが起きた際は自然に全体中断する仕組みになっているため、ログイン失敗のときも特別な処理を追加しなくてもフロー全体は止まります。

「個別スキップ」「リトライ」など、エラー時の挙動を細かく制御する設計は 第6回（制御構造） で扱います。

❓よくある詰まりと FAQ

Q1. UI要素ピッカーで要素を選んでも赤枠が出ない
UI 要素ピッカーの赤枠はブラウザ拡張機能で PAD が ON になっている Chromeでないと表示されません。
対処法：WebDriver で起動した Chrome に PAD の拡張機能をインストール → その Chrome を閉じずに「UI 要素取得用ブラウザ」として残しておくと作業しやすくなります。
Q2. 機密情報テキスト入力欄が見つからない
テキスト欄の右側にあるプルダウン（▼）をクリックし、「直接暗号化されたテキストの入力」を選択してください。アイコンや鍵マークではなくプルダウンメニューです。
Q3. ログインボタンを押しても遷移しない
利用規約チェックボックスを ON し忘れているケースが多発。チェック状態を必ず先に設定すること。
Q4. 自分のメールでログインできない
第0回で signup したアカウントを使ってください。パスワード忘れの場合は TA に依頼。
