第5回 ブラウザ自動化② 〜スクレイピング・URL直接ナビ〜

Web 上の情報を自動取得してデータテーブルに格納する力を身につける、カリキュラム最大の山場です。
<object> 埋め込み UI への対処として URL 直アクセスを習得します。

🎯到達目標

  • 「Webページからデータを抽出する」アクションでテーブルを抽出できる
  • 取得した DataTable を Excel に転記できる
  • %変数% で URL パラメータを動的に組み立て、目的の状態のページに直接遷移できる（例：staff-list.html?dept=%選択部署%&role=%選択役職%）
  • <object> 埋め込みで UI 要素が取得できない場面を正しく診断できる
  • ページネーション（複数ページの走破）の基本を知る

🪜事前準備

  • 第4回 のログインフローが手元にある
  • デモサイトの staff-list.html／staff-search-popup.html を開けることを確認

📖解説

5-A. データ抽出の基本手順

① 第4回のログインフローの続きに、スタッフ一覧ページを開く処理を追加する
開き方は次のどちらでも OK：
  • (A) UI 要素ピッカーで「スタッフ一覧」サイドバーボタンを取得 → 「Web ページのリンクをクリック」でナビゲートする
  • (B) 「Web ページに移動する」アクションで staff-list.html の URL を直接指定して飛ぶ
② 抽出アクションを配置する
アクションペインで「ブラウザー自動化 ＞ Web データ抽出 ＞ Web ページからデータを抽出する」を選び、フロー上にドラッグ＆ドロップします。
検索ボックスに 抽出 と入力すると一発で出てきます。
※ このアクションは、いま PAD が制御している Chrome（4-A で WebDriver 起動したもの）に対して動きます。別タブや別 Chrome は対象外。
③ ライブ Web ヘルパーで取得したい部分を右クリック
② のアクションを配置すると、ライブ Web ヘルパー（薄いオレンジ枠つきの専用ウィンドウ）が自動で立ち上がります。マウスを画面上で動かすと、要素ごとに枠線が出ます。
取得したいテーブル（例：スタッフ一覧の表）の上で右クリックし、出てきたメニューから次のどちらかを選びます：
  • 「要素の値を抽出」… 会社名や金額など、一つの値だけ取得したいとき
  • 「HTMLテーブル全体を抽出する」… サイト内の表をまるごと取得したいとき
④ 取得結果は変数に格納される（既定名：DataFromWebPage）
ライブ Web ヘルパーを「完了」で閉じると、抽出結果は自動で変数に格納されます。「HTML テーブル全体を抽出する」を選んだ場合はデータテーブル型の変数に入ります（Excel の表のように行×列で持っているイメージ）。
💡 変数名はリネームしておく： 既定の DataFromWebPage のままだと、複数の抽出を組み合わせたときに「どれがどれだか分からない」事故が起きます。右側の「変数」ペインで右クリック →「名前の変更」で StaffList など内容がわかる名前に変えておくのがおすすめです。
🛠️ ハンズオン課題①：sales-list.html から売上データ全件をスクレイピングして DataTable に取り込み、Excel に書き出すフローを作ってみましょう。

5-B-①. ページネーション（基本編）〜「ページャーとして設定」〜

1 ページだけでなく、「次へ」「>」などのページネーションが付いているサイトから全ページ分のデータをまとめて取得したいとき、最初に試すのは PAD 標準の機能です。

① ページャーボタンを設定する
「Web ページからデータを抽出する」アクションで通常どおりライブ Web ヘルパーを起動し、5-A の③と同じ手順でテーブルを取得します。
そのままライブ Web ヘルパー上で「次へ」などのページャーボタンを右クリックし、出てきたメニューから「要素をページャーとして設定」を選択。
② 実際に次のページに進んで、テーブルが認識されているか確かめる
ページャー設定の直後は必ず確認します。ブラウザ側で実際に「次へ」を押して次のページに進んでみる。
👀 チェックポイント：次のページのテーブルの周りに 点線（破線）の枠 が表示されていれば、PAD が「ここも同じ取得先」と認識してくれています。このまま ④ のデータ抽出元設定に進んで OK。
③ 点線が出ていなかったら、次のページでも同じ取得設定をやり直す
HTML 構造が 1 ページ目と微妙に違うサイトでは、PAD が「これは別物」と判断して点線が出ないことがあります。その場合：
  1. 次のページのテーブル上で右クリック
  2. 「HTML テーブル全体を抽出する」をもう一度選び直す
  3. 点線が表示されたら、その後ろのページも同様に確認していく（点線が出ない都度やり直す）

これで「このテーブルとあのテーブルは同じ取得対象だよ」と PAD に教え込んでいきます。

④ アクション設定に戻り、「データの抽出元」プルダウンで動作を選ぶ
  • 「すべて使用できます」を選ぶ → PAD が最後のページまで自動でページ送りしてすべて取得
  • 「最初のみ」を選ぶ → 下に 「処理する Web ページの最大数」 入力欄が出てくるので、走破したいページ数（例：10）を入力

これで、PAD が自動で「次へ」を押しながらページを送り、抽出結果を 1 つのデータテーブルにまとめてくれます。

😱 サイトによっては、最後のページまで行ってもループが止まらない 「次へ」ボタンが最終ページでも HTML 上は存在し続けるサイトが業務系には多くあります。
すると PAD が「まだ次のページがある」と誤判定してしまい、最終ページの後で空ループに突入し、フローがいつまでも終わらない／タイムアウトでエラー、という事故が起きます。
👉 そんなときは次の 5-B-②（応用編：ラベル＋移動先）で対処します
🛠️ ハンズオン課題②：customer.html の得意先一覧から、まずは 「データの抽出元＝最初のみ」＋「処理する Web ページの最大数＝1」 で最初の 1 ページだけ取得してみましょう。

5-B-②. ページネーション（応用編）〜ラベル ＋ 移動先に移動する で全走破〜

5-B-① の標準ページャーで止まらない問題に直面したら、ここで紹介する ラベル ＋ 移動先に移動する パターンに切り替えます。終端判定を自分で握れるので、どんなサイトでも確実に止められます。

ページネーションは本来「次へボタンが押せる間は繰り返す」というループ。これを PAD のアクションで明示的に書く、というのが発想です。

紙の地図でイメージすると：

  • ラベル ＝ 戻ってくるための「目印」を置く
  • 移動先に移動する ＝ その目印に戻る
  • 戻る前に If 条件 Then で「次へボタンがまだ押せるか？」を判定 → 押せる間だけ目印に戻る

終端判定のキモは「次へボタンの Disabled 属性を取得して、true になったらループ終了」というロジックです。Webページ上の要素の詳細を取得しますアクションで属性を読み取れます。

組み立て順（蓄積データテーブル方式）：
  1. 新しいデータテーブルを作成（全ページぶんを蓄積する空のテーブル）
  2. ラベル（名前：移動先）を置く
  3. Webページからデータを抽出する（「データの抽出元」＝「最初のみ」、出てきた 「処理する Web ページの最大数」＝ 1。1 ページぶんだけ抽出するように設定）
  4. Webページ上の要素の詳細を取得しますで「次へ」ボタンの Disabled 属性を取得（→ %ページャー要素%）
  5. データテーブルをマージするで、いま抽出したぶんを蓄積テーブルに追記
  6. If %ページャー要素% <> 'true' Then
    • Webページのボタンを押します（次へボタン）
    • 移動先に移動する ＝ 手順 2 の ラベル に戻る
  7. End（If を閉じる）
📌 なぜ「データの抽出元＝最初のみ」かつ「最大数＝1」にするのか： 「すべて使用できます」や大きな最大数を指定すると、ページ送りを抽出アクション側に任せることになり、5-B-① で見た止まらない問題がそのまま再発します。1 ページぶんだけ抽出 → 終端を自分で判定 → 押せるなら次へ → ラベルに戻る、と「外側のループ」を自前で持つことで、止まらない問題から完全に解放されます。
🛠️ ハンズオン課題②（応用）：5-B-① のフローを、ラベル ＋ 移動先に移動する 構造に書き換えてみましょう。最終ページまで進んだら自動で停止し、蓄積データテーブルに全行が入っていれば成功です。

5-C-①. <object> / <iframe> 埋め込み UI の限界（必読）

見た目はポップアップウィンドウなのに、その中身がこっそり「別のページ」を読み込んでいる作りになっているサイトがあります。こういう UI で PAD の「UI 要素の追加」を使おうとしても、ポップアップの外側の枠しか認識されず、中の入力欄やボタンは取得できません。
このデモサイトでも、左サイドバーの「スタッフ検索」や「スタッフ追加」を開いて PAD の UI 要素ピッカーを使おうとすると、ポップアップ内に赤い枠が表示されません。これがまさにそのパターンです。
🛠️ ハンズオン課題③：staff-search-popup.html に PAD の要素取得をかけ、「中の入力欄が取れない」現象を実際に体験してみましょう。

5-C-②. 解決策 〜埋め込みページの URL を特定して直接ナビゲート〜

ポップアップ内を操作する代わりに、その中身として読み込まれているページの URL そのものへ PAD から直接ナビゲートします。URL さえわかれば操作の再現は完了です。

  1. F12 を押して開発者ツールを開く
  2. 開発者ツールを開いた状態でポップアップを開くメニューをクリック
  3. Elements タブを開くと、一番下に新しい文字列（ポップアップの HTML ソース）が追加される
  4. その文字列をダブルクリックすると、読み込まれているページのフル URL が確認できる
使うアクション：「Web ページに移動する」。確認した URL をそのまま指定するだけで、ポップアップを開かずに同じ画面にジャンプできます。

5-C-③. URL パラメータを動的に組み立てる

業務サイトでは検索結果ページの URL にパラメータが付いていることが多く、入力フォームを操作する代わりに URL を組み立てて直接遷移する手法も使えます。

たとえば「営業部の主任だけを表示する」のような絞り込みが、URL の末尾に ?dept=営業部&role=主任 を足すだけで実現できているサイトでは、フォームに値を入れて検索ボタンを押す代わりに、PAD で URL を組み立てて「Web ページに移動する」アクション 1 つで同じ結果が得られます。

// ポップアップを操作する代わりに： dept = "営業部" role = "主任" url = "staff-list.html?dept=" + dept + "&role=" + role → Web ページに移動する: %url% （= staff-list.html?dept=営業部&role=主任 に直接ナビゲート）

業務サイトでよく見かける URL パラメータのパターン：

  • ?page=2 ページ番号の指定
  • ?search=山田 検索キーワード
  • ?dept=営業部&role=主任 複数条件（& で連結）
  • ?id=ST001 特定レコードの直接参照

🧪 実際にデモサイトで体感してみる

このサイトの staff-list.html も ?dept=...&role=... 形式の URL パラメータで絞り込みできるようになっています。下のシミュレーターで部署・役職を選ぶと、組み立てられた URL がリアルタイムに表示されます。「このURLを開く」を押すと、ポップアップ検索フォームを使わずに同じ絞り込み結果のページに飛べることが体感できます。
